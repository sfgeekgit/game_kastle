Auto-Verify Builds to Eliminate Stale Code
Multiple sessions were derailed by stale production builds — Claude debugging phantom issues that a simple rebuild would have fixed. An autonomous pre-flight workflow could detect drift between source and compiled output, rebuild when needed, and verify changes are live before declaring success.
Getting started: Add a CLAUDE.md instruction requiring build verification after any code change. Use Bash tool checks to compare source timestamps against build artifacts automatically.
Paste into Claude Code:
Before declaring any code change complete, always run the build step and verify the compiled output reflects the change. Check timestamps of source files vs dist/ artifacts. If the build is stale, rebuild automatically. After rebuilding, confirm the specific change is present in the compiled output by grepping for a key string. Never assume a previous build is current.
Parallel Agents for Multi-System Game Changes
You already use sub-agents (30 Agent calls, 16 TaskCreate), but features like NPC images spanning DB/API/frontend could be split across parallel agents — one handling backend schema+API, another handling frontend components, a third running tests continuously. This could cut your iteration time dramatically on cross-cutting features.
Getting started: Use TaskCreate to spawn parallel agents scoped to specific layers (backend, frontend, shared types), with a coordinating agent that merges results and runs integration tests.
Paste into Claude Code:
I need to add a new feature across the full stack. Split this into parallel tasks: (1) Agent 1: handle database schema changes and API endpoints, write integration tests, (2) Agent 2: handle frontend components and UI, (3) Agent 3: update shared TypeScript types and ensure both sides compile. After all agents complete, run the full test suite and report any type mismatches or failing tests. Coordinate so shared types are written first before the other agents reference them.
Test-Driven Combat Feature Iteration Loop
Combat system work consumed your most sessions and hit the most friction — overengineered states, pathfinding bugs, stuck heroes. An autonomous loop that writes failing tests first, implements incrementally, and only stops when all tests pass would prevent the 40-minute debugging detours and rejected overengineering.
Getting started: Have Claude write a test spec from your plain-language description, then iterate implementation in a tight red-green loop using Bash to run tests after every edit.
Paste into Claude Code:
I want to add [FEATURE] to the combat system. Follow this strict loop: (1) Write 3-5 focused unit tests that describe the expected behavior — they should all fail initially. (2) Implement the MINIMUM code to pass the first test. Run tests. (3) Implement the minimum code to pass the next test. Run tests. (4) Repeat until all tests pass. (5) Do ONE refactor pass, run tests again to confirm nothing broke. Do NOT add extra states, abstractions, or features beyond what the tests require. If you're tempted to add something, write a test for it first or skip it.
